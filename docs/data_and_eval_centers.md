# 数据中台与评测中台

更新后先在 `backend` 执行 `python -m alembic upgrade head`。迁移增加评测题集、用例检查点、Token 账本、知识快照和索引指针。生产 Compose 的迁移服务会先执行升级。前端入口位于导航栏。

## 数据中台

选择仓库后，可分页查找上传文档、Issue、PR 和 CI 运行。页面显示仓库同步时间与项目索引进度，并展示文档的处理状态、SHA-256、分块数和 CI 运行对应的提交。

资产目录读取现有仓库和知识库记录。上传、同步和索引操作仍通过已有页面执行。目录遵循现有令牌权限与仓库可见范围。

在“知识快照与索引切换”中，可将当前已索引的分块、检索配置及向量冻结为一个版本。实时数据继续同步。选择旧快照即可回滚，切换只更新 PostgreSQL 中的指针。关键词和向量检索都基于选定快照，实时的 GitHub 状态与仓库源码工具仍读取各自来源。启用 Milvus 时，快照要求所有分块的向量都可读取。快照内的向量由 PostgreSQL 保留，检索使用余弦相似度。默认每仓库最多 10 个快照，每个最多 2,000 个分块。

## 评测中台

1. 选择仓库，在“管理题集版本”中输入标识、名称和用例 JSON。支持数组和带 `cases` 的 JSON 对象。每题填写 `question`、`reference`，可附上唯一 `id`、`source_file`、`must_include` 等规则。
2. 发布后，在评测配置中选择题集版本。仓库维护者和所有者可以发布。同一标识的后续发布会创建新版本。可载入已发布版本，在编辑区调整内容后再次发布。
3. 选择知识快照，检查回答模型、Judge、Top-K 和预算。题数预算须覆盖整套题，且符合 `MAX_EVAL_CASES`。Token 预算须符合 `MAX_EVAL_TOKENS`。关闭模型评分后，回答环节仍可能调用 ChatAgent 模型。
4. 提交后台任务后，可以查看进度、逐题证据、硬规则与基线对比。Worker 恢复时复用已保存的结果。遇到已经开始但没有结果的用例，会保留已完成结果并将本次运行标为异常。

Token 上限适用于使用预算的评测任务。每次回答、Judge、远程 Embedding 和重排请求先在数据库预留用量。请求体字节数、协议余量和输出上限用于预留，服务商返回用量后按该值结算。请求超时或缺少用量时保留预留。预留不足时阻止请求，已有结果会保留。真实模型的预算评测要求 PostgreSQL。服务商分词和账单以提供方为准。重评分是独立任务，若原评测有 Token 上限，重评分沿用该限额。

## 发布门禁

1. 用待发布的后端版本、版本化题集和候选知识快照运行完整评测。
2. 在评测结果中点“检查发布门禁”。校验包括快照摘要、后端代码摘要、回答与评分模型、用量记录、完成题数、硬规则和当前各项指标门槛。结果通过后可将评测 ID 填入数据中台，审批索引切换。
3. 生产环境设置 `RELEASE_GATE_REQUIRED=true` 和 `RELEASE_GATE_EVAL_ID`。先确保目标仓库已选择通过评测的快照。API 启动时校验结果，缺失或不达标会拒绝启动。新环境可先在候选环境完成评测，再迁移评测记录和快照至目标环境。

本地真实验收脚本为 `scripts/verify_quality_centers.py`。它使用环境变量中的 `DEEPSEEK_API_KEY`（或 `LLM_API_KEY`）调用官方 `deepseek-flash` 作答并评分，离线资料仅使用仓库内公开的评测文档。RAGAS 语义相似度用环境变量 `DASHSCOPE_API_KEY` 调用 Embedding。脚本要求独立的 PostgreSQL `*_validation` 库和明确的 `--token-budget`。
